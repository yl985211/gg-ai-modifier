# GG-AI Modifier v5.0.0 版本更新说明 (Release Notes)

相对 `gg-ai-modifier3.0版本`，本版本把 3.0 预留的「插件中心」真正做成了可用的 **Skill 系统**，并补齐了 Google Gemini 接入、OpenAI `tool_calls` 协议、全局视觉重做，以及一批原生层稳定性修复。

---

## 🚀 一、插件中心正式上线：Skill 系统

3.0 的插件中心只是占位入口（“等待热更新下发”）。5.0 将其升级为完整的 **Skill 管理中心**：

| 能力 | 说明 |
|------|------|
| 导入 Skill | 从本地选择 `.md` 文件导入，支持命名后保存 |
| 内置 Skill | 预置「新手引导专家」，可开关启用 |
| 启用 / 禁用 | 一键切换；已启用 Skill 会同步给悬浮窗 AI |
| 删除 / 导出 | 支持单个删除，以及多选批量导出为 Markdown |
| 本地持久化 | Hive 新增 `skills` Box；文件副本写入应用私有 `skills/` 目录 |
| 原生同步 | MethodChannel `syncSkills` 写入 SharedPreferences `gg_skills` |
| 悬浮窗注入 | 悬浮窗 AI System Prompt 自动拼接已启用 Skill 内容 |

新增模型文件：

- `lib/core/models/skill_model.dart` — Skill 数据模型（id / name / content / 启用态 / 内置标记等）
- `lib/services/storage_service.dart` — 增补 `saveSkill` / `getAllSkills` / `getEnabledSkills` / `toggleSkill` / `deleteSkill`

导出路径（按系统版本适配 MediaStore）：

- Android 11+：`Documents/AI-gg/skills/`
- Android 10：`AI-gg/skills/`
- Android 9 及以下：外部存储 `AI-gg/skills/`

## 🌐 二、Google Gemini 模型支持

5.0 新增 Gemini 预设，并打通主应用与悬浮窗两条调用链：

- `llm_config.dart` 新增 `gemini` 预设（`gemini-1.5-flash`）
- 自动识别 `generativelanguage.googleapis.com`，请求地址自动补全为 OpenAI 兼容接口：`/v1beta/openai/chat/completions`
- 设置页「测试连接」对 Gemini 走专用测试逻辑，与普通 OpenAI 兼容 API 分流
- 悬浮窗 `OverlayService` 同步支持 Gemini 端点拼接与模型名称识别
- 新增依赖：`google_generative_ai: ^0.4.7`、`file_picker: ^11.0.2`

## 🔧 三、Function Calling 协议升级

主应用 LLM 服务从旧版 `function_call` 字段升级为 OpenAI 标准 **`tools` / `tool_calls`** 协议：

- 非流式响应解析 `message.tool_calls[]`，并回传 `role: tool` + `tool_call_id`
- 流式响应识别 `delta.tool_calls`，在执行工具时给出提示
- 端点统一走 `effectiveBaseUrl`（兼容 Gemini）

> 内存操作工具集本身（`search_memory` / `read_memory` / `write_memory` / `fuzzy_search` / `filter_results` / `save_address` / `freeze_value` 等）与 3.0 对齐，本版本重点是协议与接入层升级。

- 底部导航、插件中心、设置页、悬浮窗面板配色一并切换

## 📱 五、主应用交互升级

### 首页导航

- `IndexedStack` 改为 **`PageView` 滑动翻页**，支持左右滑动切换 Tab
- 底部导航与滑动联动，带 300ms 缓动动画
- 修复从悬浮窗跳转主应用页面时的状态切换体验

### 设置页

- 新增「删除自定义模型」批量选择对话框，可一次清理多个自定义预设
- 编辑当前自定义预设时，实时同步写回 `_customPresets` 并持久化
- 删除当前选中的自定义预设后，自动回退到 DeepSeek 并保存配置
- Gemini 连接测试与 OpenAI 兼容测试分流，错误提示更细（超时 / 无网络 / VPN）

## ⚙️ 六、原生层（Kotlin）能力与稳定性

`MainActivity` / `OverlayService` 有实质增强，不只是主题换色：

| 改动 | 说明 |
|------|------|
| 后台线程化 | 进程列表、附加/分离、精确/范围/模糊/AOB 搜索、读写内存等 MethodChannel 调用改为后台线程执行，结果回主线程，避免 UI 卡死 |
| 首次启动权限 | `requestAllPermissionsOnFirstLaunch()` 统一申请存储 / 悬浮窗等权限 |
| 新增通道 | `syncSkills`、`exportSkillToFile`、`exportChatToFile`、`deleteOverlayChat` |
| Skill 注入 | 悬浮窗 AI System Prompt 读取 `gg_skills`，注入已启用 Skill |
| Gemini 端点 | 悬浮窗两条 API 调用链均支持 Gemini OpenAI 兼容地址 |
| 内存引擎 | `MemoryEngine` 继续基于 Root Scanner（C++ `pread64` / `process_vm_readv`），补强地址多类型读取与机器码回填 |

C++ 扫描器架构与 3.0 一致（`scanner_root_optimized` 主力 + JNI 备用），仍使用 `-O3 -ffast-math -funroll-loops` 优化编译。

## 🐛 九、修复与优化

1. 修复原生 MethodChannel 重负载调用可能阻塞 UI 的问题（搜索 / 读写 / 进程操作改为后台线程）
2. 修复自定义模型编辑后未同步保存的问题
3. 修复删除当前自定义预设后配置状态异常的问题
4. 统一 Gemini 与 OpenAI 兼容 API 的端点解析，避免 baseUrl 拼接错误
5. 悬浮窗与主应用主题色不一致问题（统一为深蓝科技风）
6. 插件中心从不可用占位变为完整 Skill 生命周期管理
